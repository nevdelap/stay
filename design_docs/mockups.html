stay — status-marker mockups (a/d/t → words)

Mockups for replacing the single-letter status markers with full words. Screen space is not scarce and the letters are not keystrokes, so spell them out. Both surfaces change: the plain listing (stay list) and the interactive picker. These mockups are for sign-off before the change is written into stay.html and the task specs.

1. Plain listing — stay list

today (letters, tab-separated)

a alpha a dev d builds d scratch t flaky-tests exit=1 @2026-07-26 14:30 t old-run exit=0 @2026-07-26 09:12

proposed (words, name first, names padded so the brackets line up)

alpha [attached] dev [attached] builds [detached] scratch [detached] flaky-tests [terminated exit=1 @2026-07-26 14:30] old-run [terminated exit=0 @2026-07-26 09:12]

Same row shape as the picker (§2): name first, state as a bracketed suffix. The name column is padded by display width so the brackets line up, with a single space before the bracket (never two). Only terminated rows carry the exit code + time inside the brackets; a non-zero exit code is shown in red when stdout is a terminal (piped/redirected output stays monochrome). Today the output is literally <marker>\t<name> (state first); this flips it to name first and unifies the two surfaces — the plain listing and the picker now render the same row.

The focused row keeps its suffix. Today the picker hides the suffix on the highlighted row; instead the focused row shows its suffix like every other row — including the terminated exit code + time, the postmortem data the user is reading the row for. Every terminated row — focused or not — carries the exit code + time; attached/detached rows show just the word. The exit code is red on unfocused rows; the focused (reverse-video) row drops the red so the highlight is uniform.

The focused row keeps its suffix — consistency outweighs the small redundancy. The selected row differs from the others only in being reverse-video; the marker (and, for terminated, the exit code + time) is always present, so the column never has a gap under the highlight.

4. Picker — narrow terminal (graceful degradation)

Drop the timestamp first, then the exit code; keep the marker word longest. Never panic or overflow.

stay — sessions alpha [attached] builds [detached] flaky-tests [terminated exit=1] old-run [terminated exit=0] scratch [detached]

…and at ~30 columns the whole suffix drops and only the names remain.

5. Edge — multi-pane session with one dead pane

A manually-split session where one pane died but others live is not terminated — it still has a live pane, so it shows attached/detached, not terminated. This also composes correctly with auto-detach: the active pane dying detaches the user, but a session with surviving panes is not "terminated." Stay-created sessions are single-pane, so this is an edge, not the common case.

6. Picker — content-sized and centered (wide / tall terminal)

On a full-screen terminal the full-width, full-height box looks out of place. Instead the picker shrink-wraps to its content and centers itself in the terminal. The blue rounded border, grey interior, and black terminal around it are the actual target rendering, not just illustration: a ratatui Block with Borders::ALL + BorderType::Rounded and a blue border style, filled with a background colour, drawn on a centred content-sized Rect over a frame cleared to the terminal background.

  • Height = number of sessions (plus the title border, separator, and status line) — never stretched to fill a tall terminal.
  • Width = the widest line, whether a session row or the status line — exactly as wide as the widest content needs, no wider. The status line stays on one line; it only flows (wraps) when the terminal is narrower than that one line.
  • Centered in the terminal when the terminal is larger than the box (both axes); the rest of the terminal is empty space around it.
stay — sessions create new session alpha [attached] dev [attached] flaky-tests [terminated exit=1 @2026-07-26 14:30] ↑/↓ select · Enter attach · c create · k kill · r recreate · e edit name · v view-only · l low-priority · Esc quit

The blue outline is the content-sized box; the dark area around it is the empty terminal. Edges: if there are more sessions than terminal rows, height caps at the terminal and the overflow is hidden (scrolling is a separate, pre-existing gap — today the picker already drops rows past the bottom). If the longest row is wider than the terminal, width caps at the terminal and the §4 narrowing rules (drop time, then exit code) apply.

7. Picker — create row, focused by default

The session list gains a create row at the top. On open it is the first row and the default selection, so creating a new session is just enter — no need to arrow to it. Attaching to an existing session means arrowing down past the create row. The c keybinding is kept: pressing it focuses the create row and opens the name prompt immediately (one step, not focus-then-Enter). Creating always goes through the name prompt — there is never a default name.
